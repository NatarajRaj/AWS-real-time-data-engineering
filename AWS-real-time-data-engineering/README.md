\## Overview

This project demonstrates an end-to-end real-time data pipeline using AWS services.


\## Architecture

Event Producer → Kinesis → Firehose → S3 (Bronze) → Spark → S3 (Silver) → Spark → S3 (Gold) → Athena → Power BI  

Critical alerts are handled using AWS Lambda and SNS.



**Generator → Kinesis → Firehose → S3 Bronze → Spark → S3 Silver → Spark → S3 Gold → Athena → Power BI**

**                       ↘ Lambda → SNS → Email/SMS**





The **HOT path** is designed for low-latency alerts, while the **COLD path** supports analytics and reporting.

---

## Technologies Used

- **Programming:** Python  
- **Streaming & Ingestion:** AWS Kinesis Data Streams, Kinesis Firehose  
- **Storage:** Amazon S3 (Bronze / Silver / Gold)  
- **Processing:** Apache Spark / PySpark  
- **Alerting:** AWS Lambda, Amazon SNS  
- **Analytics:** Amazon Athena, Power BI  

---

## Key Features

- Real-time streaming ingestion
- Bronze–Silver–Gold data lake architecture
- Schema enforcement, validation, and deduplication
- Fault-tolerant Spark processing with checkpoints
- Event-driven alerting for failed or high-risk transactions
- Analytics-ready curated datasets

---

## Alerting (HOT Module)

Critical transaction events (e.g., failed transactions or threshold breaches) are processed through a **HOT module**:

- AWS Lambda evaluates incoming events
- Business rules are applied in real time
- Alerts are published to Amazon SNS
- Notifications are delivered via **Email and/or SMS**

This design ensures **low latency, scalability, and decoupled notification delivery**.

---

## How to Run

1. Create and start the **Kinesis Data Stream**
2. Run the **Python data generator** to push events into Kinesis
3. Configure **Kinesis Firehose** to deliver data into S3 Bronze
4. Run Spark jobs to process:
   - Bronze → Silver (cleaning & deduplication)
   - Silver → Gold (aggregations)
5. Create Athena tables on Gold data
6. Connect **Power BI** using Athena and build dashboards

---

## Summary

This project showcases a **production-style real-time data pipeline** using AWS managed services and Spark, with a clear separation between:
- **Streaming ingestion**
- **Data lake processing**
- **Real-time alerting**
- **Analytics and reporting**

It is designed to reflect real-world data engineering patterns used in financial and transactional systems.

**Step by step on execution:**
1️⃣ DATA GENERATOR (Simulated Transactions → Kinesis)
"Transaction events are generated by upstream systems(data generator) and ingested into Kinesis for scalable, durable streaming."

2️⃣ KINESIS → FIREHOSE → S3 BRONZE
⚙️ No code needed (AWS Managed)

Firehose configured to:
Source: Kinesis Data Stream
Destination: S3
Path: s3://transaction-bronze/year=/month=/day=/

“Firehose handles batching and reliably lands raw data into S3 Bronze.”
“Firehose delivers raw events into S3 Bronze for traceability and replay.”

3️⃣ HOT MODULE – LAMBDA → SNS (ALERTING)
“Lambda evaluates critical events and SNS sends SMS/email alerts.”

4️⃣ BRONZE → SILVER (Spark Structured Streaming)
“Silver layer contains clean, deduplicated, validated data.”

5️⃣ SILVER → GOLD (Aggregations)
“Gold layer stores business-ready aggregated datasets.”

6️⃣ POWER BI (Athena / SQL on GOLD)
🔗 Power BI connects via:
Athena connector
AWS ODBC driver

“Power BI consumes Gold data via Athena for dashboards.”
